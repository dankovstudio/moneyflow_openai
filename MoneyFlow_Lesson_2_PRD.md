# MoneyFlow — PRD второго урока

Продолжение PRD первого урока. Исполнитель — Claude Code (Opus) в bb: проект lesson0, папка ~/Desktop/lesson1, главный тред «боевой». Это основной PRD для backend, SQLite, CoinGecko API, Telegram, MCP и сценария урока. Отдельный MoneyFlow_Lesson_2_Frontend_Update_PRD.md задаёт точные изменения интерфейса; фронт обновляется по нему **до урока** (фаза 0), и на уроке его результат уже готов. Работающий фронт первого урока — исходный код, который агент обязан осмотреть перед правками; не угадывать структуру файлов.

## 1. Результат урока

Из frontend-прототипа сделать локальное приложение: сайт и Telegram-бот записывают траты в одну SQLite; сайт показывает общие итоги в GBP; крипторасходы в USDT, USDC, ETH, BTC, SOL оцениваются через CoinGecko API в GBP на момент ввода. Отдельный новый чат Claude, открытый вне проекта, читает траты через созданный MoneyFlow MCP и анализирует их. В самом приложении AI-помощника нет.

Объяснение для зрителей: «Сайт и бот сообщают о расходе нашему бэкенду. Он узнаёт курс у CoinGecko, если расход в крипте, и сохраняет результат в базе. Через MCP Claude в другом чате может спросить наше приложение о тратах». Не объяснять GET/POST и устройство протокола.

Финальная последовательность показа: сайт → CoinGecko → SQLite/DBeaver → Telegram → сайт/DBeaver → новый чат и MCP. Docker Compose, публичный сервер и деплой — следующий урок.

## 2. Исходное состояние и границы

- Первый урок: React + TypeScript + Vite, четыре GBP-счёта NatWest, Revolut, Payoneer, Cash, 12 вымышленных транзакций сентября 2026, форма добавления в памяти. В первом PRD исходные итоги: income £5,050.00, expenses £2,598.39, net £2,451.61, total balance £4,751.61. После одной пробной траты Tesco £12.50 с NatWest в Groceries: expenses £2,610.89, net £2,439.11, NatWest £3,203.91, total balance четырёх счетов £4,739.11. Если реальный фронт с урока отличается, Claude сначала фиксирует отличия и использует его реальные исходные данные.
- Только локальный backend и SQLite. Без Docker, деплоя, реальных банковских данных, авторизации пользователей, истории курсов, on-chain подключения и AI API внутри MoneyFlow.
- Один пользователь. Telegram-бот получает сообщения локальным polling, без публичного URL; разрешённый chat ID ограничивает запись. Запущен один экземпляр бота.
- MCP только для чтения, локальный HTTP адрес /mcp на 127.0.0.1. Для демонстрации использовать второй локальный Claude Code на том же компьютере, но новый чат в другой пустой папке. Облачный чат не видит localhost без отдельного туннеля; туннель и деплой не входят в урок.
- Сохранить существующий вид дашборда и форму, добавить ровно необходимые элементы. Не переписывать фронт с нуля.

### Принятые решения (обязательны)

- **Крипта всегда «сейчас».** Криптотрата записывается датой сегодняшнего дня по Europe/London и курсом CoinGecko в момент сохранения. Для крипты поле даты не редактируется; задним числом крипту не вводим. Дата GBP-операции — от 2026-09-01 до сегодня.
- **Баланс при выборе месяца** — остаток на конец выбранного месяца: начальный остаток + все операции с датой до последнего дня месяца включительно. Income, Expenses, Net и категории — только за выбранный месяц.
- **Минимальная сумма:** операция, которая после пересчёта стоит меньше £0.01, отклоняется с понятной ошибкой и не записывается.
- **Урок идёт 30 сентября 2026**, поэтому криптотраты «сегодня» попадают в сентябрь 2026; выбор месяца всё равно нужен для будущих месяцев.

## 3. Общие правила данных

1. SQLite — единственный источник истины. Сайт, бот и MCP пользуются общим серверным сервисом операций; ни бот, ни браузер не записывают базу самостоятельно. В первый запуск один раз импортировать данные первого урока; перезапуск не создаёт повторных записей.
2. Денежные суммы итогов и балансов хранить как целые пенсы. Для исходного количества криптоактива и курса сохранить точное десятичное значение, идентификатор монеты, момент получения котировки и рассчитанную сумму GBP. Корректно обрабатывать дроби BTC и SOL, не терять точность из-за двоичных float. При ответе CoinGecko без корректного курса операцию не сохранять.
3. Добавить учебный счёт Crypto Wallet с условным начальным учётным остатком £1,000.00. Это GBP-остаток для учебного дашборда, а не утверждение о реальных монетах в блокчейне; его не переоценивать при изменении рынка. До новых трат total balance пяти счетов £5,751.61. Сентябрьские income, expenses и net из первого урока не меняются.
4. Криптооперация уменьшает учётный GBP-остаток Crypto Wallet на зафиксированную GBP-сумму. В агрегатах и категориях она участвует как обычный expense в GBP. Фактическое количество монет сохраняется и видно рядом с GBP-суммой.
5. Для Telegram использовать дату получения сообщения по Europe/London и сохранить UTC-время создания. Сентябрь 2026 должен оставаться доступен, но добавленный в более позднем месяце расход не должен «пропадать» из-за фиксированного периода: добавить простой выбор месяца или общую ленту последних операций с возможностью перейти к нужному месяцу.
6. Повторное получение одного Telegram-сообщения не добавляет вторую операцию. Неверная сумма, пустое описание, неподдерживаемая монета или ошибка цены не создают запись.
7. Локальные ключи только в .env; .env.example содержит имена переменных, SQLite и .env игнорируются Git.

### Криптоактивы

| Ввод пользователя | CoinGecko coin ID |
|---|---|
| USDT | tether |
| USDC | usd-coin |
| ETH | ethereum |
| BTC | bitcoin |
| SOL | solana |

Бэкенд запрашивает у CoinGecko цену выбранной монеты непосредственно в GBP. Для USDT и USDC тоже использовать реальную котировку, не приравнивать их механически к одному USD. В этом уроке названия обозначают перечисленные CoinGecko монеты; сети, контрактные адреса, комиссии и стейблкоин-пеги отдельно не моделируются.

«На момент покупки» в уроке означает момент записи операции. Для расхода, который вводят задним числом, текущую котировку не выдавать за историческую. Уже сохранённая GBP-сумма никогда не пересчитывается вслед за рынком.

### Сайт

Существующая форма предлагает GBP, USDT, USDC, ETH, BTC, SOL. Для GBP сохранить текущие правила формы. Для крипты вводятся количество, описание, категория и дата; счёт Crypto Wallet выбран автоматически. Через собственный backend показать в форме ориентировочную стоимость в GBP до отправки, но при сохранении backend получает/фиксирует окончательную котировку; предварительная оценка может чуть отличаться. Ключ CoinGecko не отправлять в браузер.

В списке операция показывает, например, «0.1 ETH · Helius» и финальные £…; дашборд и остатки используют GBP. Пять активов работают на узком экране. Форма не должна позволять выбрать недопустимое сочетание, например ETH на NatWest.

### Telegram

Понятные текстовые сообщения, без свободного AI-парсинга:

- Обычный расход: «12.50 Tesco / NatWest / Groceries».
- Крипта: «0.1 ETH Helius», «20 USDT Netflix», «15 USDC Hosting», «0.001 BTC Service», «0.5 SOL Coffee». Допустить необязательную запятую между количеством/тикером и описанием.

Для крипты по умолчанию категория Other и счёт Crypto Wallet. Бот подтверждает исходное количество, курс и итог GBP, полученные из общей серверной логики. Команда /start объясняет оба формата. Неподдерживаемый символ сопровождается перечнем пяти разрешённых.

### MCP

Вынести на локальный HTTP endpoint /mcp два инструмента только для чтения:

- list_expenses: месяц, ограниченный размер списка; дата, описание, категория, счёт, сохранённая GBP-сумма и исходный актив с количеством.
- spending_summary: месяц, общие расходы в GBP и суммы по категориям.

Оба инструмента читают те же данные через общий сервис. Никакого произвольного SQL, изменения операций, выдачи .env, API-ключей и пути к закрытым файлам. Выводы по данным делает второй чат Claude.

## 4. Треды и правило поэтапной работы

**Треды в bb (проект lesson0, одна папка ~/Desktop/lesson1):**

- **«боевой»** — главный тред и project manager. Делает фазу 0 до урока, на уроке запускает саб-треды через `bb thread spawn`, отвечает ведущему, проверяет результат и делает интеграцию (фаза 3). Сам крупный код на уроке не пишет, чтобы оставаться свободным для вопросов.
- **Саб-тред «backend»** — фаза 1.
- **Саб-треды «telegram» и «mcp»** — фаза 2, запускаются параллельно только после принятой фазы 1.

Все саб-треды работают в одной папке, поэтому: зависимости для всех модулей ставит только саб-тред backend; саб-треды telegram и mcp не запускают `npm install`, не меняют package.json, общие схемы, frontend и файлы друг друга. Если контракта не хватает, саб-тред сообщает об этом «боевому» и останавливается.

**Фиксированные технические решения (не выбирать заново):**

| Что | Значение |
|---|---|
| Frontend | Vite на http://localhost:5173, прокси `/api` → http://127.0.0.1:8787 |
| Backend | Node 22 + TypeScript через `tsx`, Express 5, `127.0.0.1:8787` |
| База | встроенный `node:sqlite` (без нативных сборок), файл `~/Desktop/lesson1/data/moneyflow.sqlite` |
| Общий контракт | `shared/contract.ts` — типы, счета, категории, активы, коды ошибок; импортируют и фронт, и backend |
| Каталоги | `server/` — backend и общий сервис; `server/telegram/` — бот; `server/mcp/` — MCP |
| Команды | `npm run dev` — фронт + backend вместе; `npm run dev:web`, `npm run dev:api`, `npm run bot` |
| MCP | `http://127.0.0.1:8787/mcp`, официальный `@modelcontextprotocol/sdk`, Streamable HTTP |
| Telegram | long polling через `fetch` к Bot API, без сторонних библиотек, отдельный процесс `npm run bot` |
| Секреты | `.env`: `COINGECKO_DEMO_API_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ALLOWED_CHAT_ID` |

**API (контракт между фронтом и backend, типы в `shared/contract.ts`):**

- `GET /api/health` → `{ ok: true }`.
- `GET /api/dashboard?month=YYYY-MM` → выбранный месяц, список доступных месяцев (от 2026-09 до текущего), текущий месяц и сегодняшняя дата по Europe/London, итоги месяца, пять счетов с остатком на конец месяца, категории, операции месяца (новые сверху).
- `GET /api/quote?asset=ETH&quantity=0.1` → предварительная оценка: курс GBP, сумма в пенсах, время котировки. Ничего не записывает.
- `POST /api/transactions` → GBP: `asset, type, amount, account, category, description, date`; крипта: `asset, type: expense, quantity, category, description` (счёт Crypto Wallet и сегодняшняя дата ставятся на сервере). Ответ 201 с сохранённой операцией.
- Ошибки: `{ error: { code, message, fields? } }`; коды `validation_failed`, `unsupported_asset`, `amount_too_small` (400), `coingecko_key_missing` (503), `quote_unavailable` (502).

### Правило поэтапной работы

После **каждой** фазы Claude останавливается, выдаёт ведущему подробную инструкцию по ручной проверке и ждёт явной команды продолжить. В каждой инструкции указывать реальные команды, URL и порты, абсолютные пути файлов, что нажать и ввести, ожидаемое поведение/цифры, 2–4 типичные причины сбоя и как их проверить. Автоматические тесты не заменяют ручной инструкции.

Саб-треды telegram и mcp запускаются только после принятой фазы 1. Интеграцию делает тред «боевой» после завершения обоих.

## 9. Критерии готовности

- Обычный расход и все пять активов вводятся через сайт, сохраняются в SQLite и отображаются в GBP с исходным количеством/символом.
- Те же форматы принимает Telegram; он использует ровно ту же логику бэкенда и ту же базу.
- Крипторасход фиксирует реальную CoinGecko котировку на момент ввода; будущие колебания рынка не переписывают запись.
- DBeaver открывает тот же файл по абсолютному пути, выданному Claude.
- Второй локальный чат без папки проекта видит свежие расходы через два read-only инструмента MoneyFlow MCP и может проверить вывод по сайту.
- В конце каждой фазы ведущий получил точную инструкцию проверки и подтвердил результат перед продолжением.
