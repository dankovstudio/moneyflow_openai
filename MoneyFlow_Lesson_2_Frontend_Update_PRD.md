# MoneyFlow — PRD обновления фронта для второго урока

Сопутствующий документ к MoneyFlow_Lesson_2_PRD.md. Только изменения существующего React + TypeScript + Vite интерфейса первого урока. Общие правила хранения, котировок, Telegram и MCP заданы основным PRD; этот документ задаёт поведение сайта. Выполняется **до урока** в треде «боевой» (фаза 0 основного PRD), когда backend ещё не существует. Технические решения, порты и контракт API — в разделе 4 основного PRD.

## 1. Задача

Пользователь должен добавлять обычные расходы в GBP и расходы в USDT, USDC, ETH, BTC, SOL через уже существующую форму. Для каждой криптооперации сайт показывает оценку в GBP перед сохранением, после сохранения — исходное количество монет и окончательную GBP-сумму, которую рассчитали и записали на бэкенде. Операции остаются на сайте после обновления страницы и доступны по месяцам.

Не делать новый дизайн с нуля. Сохранить стиль, структуру, адаптивность и привычные сценарии первого урока. Минимально изменить форму, список операций, карточку счетов и выбор периода.

## 2. Связь с бэкендом

- Источник данных — бэкенд и его SQLite. Локальный массив первого урока использовать только для однократного серверного seed, после чего фронт не подменяет им ответы бэкенда.
- Фронт не обращается непосредственно к CoinGecko, не хранит Demo API key и не рассчитывает окончательную GBP-сумму. Для предпросмотра использует подготовленную бэкендом оценку, а после отправки показывает сохранённую транзакцию/итоги, возвращённые бэкендом.
- Единицы учёта на дашборде — GBP. В сохранённой криптооперации дополнительно отображаются исходный символ и количество, например «0.1 ETH» и «£…». Курс остаётся зафиксированным в записи и не обновляется вместе с ценой монеты.
- Контракт данных и ошибок задать в `shared/contract.ts` по разделу 4 основного PRD; backend на уроке реализует его без изменений. Типы не дублировать вручную.
- Все запросы идут на относительный `/api/...`; в dev Vite проксирует их на http://127.0.0.1:8787. Пока backend не запущен, сайт показывает понятную ошибку соединения и кнопку повтора — это ожидаемое состояние до фазы 1.
- Дашборд и форма должны поддерживать данные, добавленные ботом, без специальных Telegram-компонентов: при обновлении сайта показываются те же строки.

## 3. Что меняется в форме

1. Существующие Type, Amount, Account, Category, Description, Date сохраняются. Для расхода появляется выбор актива: GBP, USDT, USDC, ETH, BTC, SOL. Для дохода в рамках урока оставить только GBP, без обещания мультивалютных доходов.
2. Для GBP оставить прежнюю валидацию: положительная сумма с точностью до двух десятичных знаков; обычные счета NatWest, Revolut, Payoneer, Cash. GBP-форма не требует CoinGecko.
3. Для USDT, USDC, ETH, BTC, SOL поле Amount означает **количество монет**, может иметь разумную дробную точность (в том числе 0.001 BTC или 0.1 ETH), а не фунты. Подпись и подсказка меняются вместе с активом. Счёт автоматически становится Crypto Wallet; неверные сочетания актив/счёт не отправляются. Дата для крипты не редактируется: показывается «Today, …», запись и курс берутся в момент сохранения.
4. Описание и категория остаются обязательными/выбираемыми по прежним правилам. Для демонстрации: Amount 0.1, Asset ETH, Description Helius, Category Other. Другие контрольные примеры: 20 USDT Netflix, 15 USDC Hosting, 0.001 BTC Service, 0.5 SOL Coffee.
5. После ввода количества и выбора актива получить через свой backend **предварительную** оценку GBP. Не делать сетевой вызов на каждый символ ввода: запрашивать после завершения редактирования поля либо с разумной задержкой. Текст «Estimated £…» отделить от итоговой суммы: перед сохранением котировка может поменяться.
6. На Save фронт передаёт исходное количество и тикер бэкенду. Кнопка блокируется на время отправки, повторные нажатия не создают дубли. Успех закрывает форму, показывает операцию и пересчитывает все блоки из сохранённых данных. Не рассчитывать GBP в браузере по ранее полученному предпросмотру.
7. Если ключ не настроен, CoinGecko временно недоступен, цена не пришла или символ неподдерживаемый, показать понятное сообщение и сохранить введённые поля формы для повторной попытки. Не показывать «успех» и не вставлять запись локально.
8. Валидация рядом с полем: пустое/отрицательное/некорректное количество, сумма меньше £0.01 после пересчёта (ошибка `amount_too_small` от backend), неверный актив, пустое описание. Существующие клавиатурные сценарии и закрытие формы через Escape сохранить.

## 4. Дашборд и даты

- В списке операций для крипты рядом с GBP-суммой показывать исходную сумму с тикером. Допустимо «Helius · 0.1 ETH» в описании и «−£…» в сумме; пользователь должен различать оба значения с первого взгляда. Подробности могут раскрывать сохранённый курс и время котировки, если это не усложняет интерфейс.
- Сводка Income, Expenses, Net и расходы по категориям всегда в GBP; крипторасход включается в те же итоги и категорию. Новая карточка Crypto Wallet показывает его условный GBP-остаток. Никаких графиков рыночной цены и изменения фактического количества монет на карточке.
- Данные первого урока за сентябрь 2026 остаются доступны. Добавить простой выбор месяца или эквивалентное понятное переключение и видимость новых операций вне сентября. После добавления операции с датой другого месяца фронт переключается на её месяц. Дата по умолчанию для GBP-операции — текущая дата в Europe/London (из ответа backend), а не захардкоженное 2026-09-26; допустимый диапазон — от 2026-09-01 до сегодня.
- При смене месяца суммы, категории и список строятся из данных выбранного периода; баланс счетов — остаток на конец выбранного месяца (начальный остаток + все операции до последнего дня месяца). Claude должен явно показать, какой месяц выбран, чтобы записи Telegram не казались потерянными.
- Отображать загрузку, ошибку соединения с backend и пустой период; не подменять ошибку исходными mock-данными и не создавать иллюзию сохранения в памяти.

## 5. Проверка для преподавателя

**До урока (фаза 0), без backend:** `npm run build` без ошибок; `npm run dev` открывает http://localhost:5173 и показывает ошибку соединения с backend и кнопку «Try again», без старых mock-данных; форма в браузере не открывается без данных. Если агент проверял UI на временном моке вне репозитория, он называет это и мок удаляет.

**На уроке, после фазы 1:**

Это фронт-часть ручной инструкции в конце фазы «Основа» основного PRD. Claude обязан подставить фактический URL, команды, месяц и котировки:

1. Запустить сайт и backend; убедиться, что исходные данные первого урока пришли из SQLite. Сентябрьские income £5,050.00, expenses £2,598.39 и net £2,451.61 совпадают с первым PRD при совпадающем демо-наборе.
2. Создать £12.50 Tesco на NatWest/Groceries в сентябре. Проверить расходы и счёт по основному PRD, обновить страницу и убедиться, что операция осталась.
3. Открыть форму, выбрать ETH, ввести 0.1 и Helius. Увидеть Estimated GBP, сохранить, увидеть исходное 0.1 ETH и финальную £-сумму. Сверить изменение Expenses, Net и Crypto Wallet на одну и ту же сумму.
4. Повторить по одному расходу для USDT, USDC, BTC и SOL с небольшими положительными количествами. Убедиться, что каждый исходный символ виден, суммы в GBP различаются согласно полученным курсам, в итоге нет USD и не используется «USDT = ровно $1».
5. Обновить сайт и перезапустить backend; все записи и зафиксированные GBP-суммы остались. Добавить новую операцию текущим месяцем и сразу найти её через переключение месяца.
6. Отправить обычный и крипторасход из Telegram (после отдельной фазы бота), обновить сайт и проверить совпадение количества, категории, описания и GBP-суммы с ответом бота и строкой SQLite.
7. Отключить backend или имитировать ошибку курса в тестовой копии: интерфейс показывает понятную ошибку, не придумывает курс и не изображает успешную запись.

Если реальный frontend первого урока не совпадает с примерными названиями компонентов, Claude указывает реальные места в коде и сохраняет фактический дизайн.

## 6. Критерии готовности

- Один существующий интерфейс поддерживает GBP и пять криптоактивов, не превращаясь в отдельный крипто-дашборд.
- Для крипты видны и оригинальная сумма, и зафиксированная GBP-стоимость; предпросмотр не принимается за окончательную запись.
- GBP-итоги, категории, баланс Crypto Wallet и операция из Telegram согласованы с бэкендом и SQLite.
- Refresh и перезапуск не удаляют данные; текущий месяц и сентябрьские демо-данные доступны.
- Форма работает на десктопе, узком экране и с клавиатуры; ошибки CoinGecko не создают ложных операций.

## 7. Вне объёма фронта

Прямой CoinGecko API в браузере, отдельный AI-чат на сайте, подключение кошелька, мультивалютный баланс по монетам, автоматическая переоценка, комиссии сетей, исторические цены, полноценная система счетов и переводов, новый дизайн, Docker и деплой.
