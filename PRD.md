# MoneyFlow — PRD первого урока

## 1. Задача

У человека есть несколько счетов, но нет одного места, где он видит расходы за месяц, категории трат и остатки по счетам. На уроке мы создаём с нуля работающий **frontend-прототип** личного финансового дашборда. Это учебный продукт с вымышленными данными, а не банковское приложение.

**Результат урока:** локально запущенный адаптивный интерфейс; новую операцию можно добавить через форму, после чего все связанные суммы пересчитываются. После обновления страницы добавленная операция исчезает — это ожидаемая граница текущей версии.

## 2. Для кого и что важно

- Один пользователь с четырьмя счетами: **NatWest, Revolut, Payoneer, Cash**.
- За несколько секунд понять: сколько пришло, сколько потрачено и сколько осталось в этом месяце.
- Увидеть расходы по категориям, остаток на каждом счёте и последние операции.
- Добавить доход или расход без ручного изменения кода.

## 3. Объём первого урока

- **Стек:** React + TypeScript + Vite; CSS и небольшие зависимости на усмотрение Codex. Проект создаётся во время урока в пустой папке.
- **Язык интерфейса:** английский. Валюта — только GBP; даты в формате `en-GB`.
- **Демо-период:** сентябрь 2026 года; заголовок явно говорит `September 2026 · Demo`. Выбор других месяцев пока не нужен. Дата новой операции должна попадать в этот месяц; первоначальное значение — `2026-09-26`.
- **Данные:** локальный вымышленный набор в коде. Операции и начальные остатки заданы отдельно. При первом открытии приложения показывается один и тот же исходный набор.
- **Изменения:** только в памяти текущей вкладки React. Не использовать `localStorage`, `sessionStorage`, IndexedDB, backend или базу данных.

### Дашборд

1. Шапка: MoneyFlow, период, заметная кнопка `Add transaction`.
2. Сводка: `Income`, `Expenses`, `Net` за период; отдельно — `Total balance` по всем счетам. `Net = Income - Expenses`.
3. Счета: остаток каждого из четырёх счетов.
4. Расходы по категориям: сумма и визуальное сравнение; учитываются только расходы. Если диаграмма неудобна на узком экране, достаточно аккуратных горизонтальных полос.
5. Последние операции: дата, описание, счёт, категория, тип и сумма. Новые операции видны сразу; порядок — новые даты сверху. Доход и расход визуально различимы не одним лишь цветом.

### Добавление операции

Форма или диалог с полями: `Type` (income/expense), `Amount` (GBP, положительное число с максимум двумя знаками после точки), `Account`, `Category`, `Description`, `Date`. Для дохода показывать категории Salary, Freelance, Other; для расхода — Housing, Groceries, Transport, Dining, Shopping, Subscriptions, Health, Other. Описание обязательно.

При отправке проверять поля и дату в пределах демо-периода. Ошибки показывать рядом с соответствующим полем. Успешная отправка закрывает форму, добавляет операцию в текущий список и пересчитывает сводку, категории и остаток счёта. Отмена ничего не меняет. Кнопка и поля доступны с клавиатуры; диалог можно закрыть через Escape.

## 5. Этапы реализации — запускать по одному

**Phase 1 — Foundation.** Создать проект, установить необходимые зависимости, запустить локально. Остановиться после работающего пустого приложения. Не строить дашборд на этом шаге.

**Phase 2 — Dashboard.** Добавить типы данных, демо-операции, расчёты и адаптивный интерфейс. Проверить суммы из раздела 4 и посмотреть страницу в браузере. Форма добавления пока не нужна.

**Phase 3 — Interaction.** Добавить форму, проверку ввода и обновление данных в памяти. Проверить демонстрационную операцию и затем обновить страницу.

**Phase 4 — QA.** Исправить обнаруженные проблемы отображения, доступности и расчётов; проверить широкий и узкий экран, пустые состояния там, где они реально возникают. Не расширять функциональность.

**Phase 5 — Share.** Зафиксировать проверенное состояние в Git и отправить исходный код в GitHub в ходе урока. Репозиторий заранее не готовить. Не включать `node_modules` и секреты.

Следующий этап начинать только после явной команды ведущего. По завершении каждого этапа Codex кратко сообщает, что сделал, как проверил и что осталось для следующего этапа.

## 6. Критерии готовности первого урока

- Локальное приложение запускается и выглядит читаемо на десктопе и телефоне.
- Исходные суммы и остатки совпадают с проверочными итогами; расходы по категориям суммируются в £2,598.39.
- Демонстрационная операция видна в списке и обновляет все связанные суммы; отмена и невалидный ввод не меняют данные.
- Refresh возвращает исходные демо-данные без ошибок и без скрытого сохранения.
- Проект можно получить из GitHub и запустить обычными командами установки зависимостей и старта.

## 7. Вне объёма

Авторизация, реальные банковские данные и интеграции, мультивалютность, переводы между счетами, редактирование/удаление операций, фильтры и другие месяцы, Telegram, AI API, сервер, база данных, Docker, деплой и постоянное хранение. Не добавлять их автоматически, даже если они кажутся логичным продолжением.
